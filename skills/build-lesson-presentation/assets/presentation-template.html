Механизм Реализация Проверка

Концепция

Начинаем с инвариантов

Contract

Какие входы, выходы и ошибки видит вызывающая сторона?

State

Что меняется между шагами и кто владеет этим состоянием?

Failure model

Как система отменяет, повторяет и безопасно восстанавливает работу?

Фрагменты появляются только по явному переходу: стрелка вправо, пробел или кнопка «Далее».

Contract → код

Узкий интерфейс, явный результат

from typing import Protocol

class Tool(Protocol):
    async def invoke(
        self,
        request: ToolRequest,
        *,
        deadline: float,
    ) -> ToolResult:
        """Return a typed result; never hide failure."""

Что проверяем

  • Типизированные границы
  • Deadline и cancellation
  • Ошибка — часть контракта
  • Deterministic fake для тестов

Поток выполнения

Один цикл — четыре наблюдаемых шага

Observe

Принять вход и восстановить checkpoint.

Decide

Выбрать действие в пределах бюджета.

Execute

Выполнить side effect идемпотентно.

Record

Сохранить результат и audit event.

Практика

Лабораторная: реализовать механизм

Задача

Реализуйте минимальный исполнитель с typed state, deadline и checkpoint. Фреймворки агентов использовать нельзя.

Ограничения

  • Детерминированные тесты без live API.
  • Повторный запуск не дублирует side effect.
  • Отмена корректно проходит через все слои.

Результат

Код, тесты и короткая ADR с описанием принятых компромиссов.

Timebox: 45–60 минут.

Gate

Готово — значит доказано

Проходит

  • Happy path и contract tests
  • Timeout, retry и cancellation
  • Replay после checkpoint
  • Наблюдаемый audit trail

Защита решения

Объясните инварианты, одну альтернативу и границу, после которой выбранный дизайн перестаёт работать.
