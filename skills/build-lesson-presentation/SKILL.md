# Build Lesson Presentation

Создавать презентацию как учебный интерфейс, а не как декоративный лендинг.
Сохранять техническую глубину урока и один визуальный язык во всём треке.

## Собрать содержание

1. Прочитать `AGENTS.md`, README текущего урока и соответствующий модуль в
   `docs/senior_ai_agent_engineer_2026.md`.
2. Определить аудиторию, цель урока, ожидаемый артефакт и Gate.
3. Построить повествование в порядке:
   - проблема и deterministic baseline;
   - contracts, invariants и state ownership;
   - execution trace или схема;
   - минимальная реализация механизма;
   - fault и security cases;
   - самостоятельная практика;
   - Gate и критерии доказательства.
4. Оставить одну основную мысль на слайд. Не переносить README целиком.
5. Показывать framework mapping только после from-scratch механизма.

## Создать презентацию

1. Создать файл из общего шаблона:

   ```bash
   python3 skills/build-lesson-presentation/scripts/create_presentation.py \
     lessons/module_XX_topic/presentation.html \
     --title "Название урока" \
     --subtitle "Короткое обещание результата" \
     --module "Модуль XX" \
     --description "Что студент сможет доказать после урока"
   ```

2. Сохранить встроенные CSS и JavaScript как общий runtime. Менять их только
   при исправлении самого шаблона.
3. Заменить демонстрационные `.slide` внутри отмеченного authoring-блока.
4. Использовать готовые паттерны из
   [библиотеки слайдов](references/slide-patterns.md).
5. Следовать [визуальной системе](references/design-system.md).
6. Не подключать CDN, web fonts, analytics и runtime-зависимости. Презентация
   должна работать напрямую через `file://`.

## Ограничить визуальный шум

- Использовать спокойный светлый canvas, одну акцентную семью цветов и системные
  шрифты.
- Не применять neon, glow, glassmorphism, большие градиенты, псевдо-терминал на
  каждом слайде, бесконечную анимацию и автопереходы.
- Анимацию запускать только действием пользователя и отключать при
  `prefers-reduced-motion`.
- Ограничивать обычный слайд примерно 60–90 словами, а code block — фрагментом,
  который читается без уменьшения шрифта.
- Показывать состояние не только цветом: добавлять текст, подпись или форму.
- Давать диаграмме текстовое описание или эквивалентный список.

## Проверить

1. Запустить статическую проверку:

   ```bash
   python3 skills/build-lesson-presentation/scripts/validate_presentation.py \
     lessons/module_XX_topic/presentation.html
   ```

2. Открыть файл через `file://` и проверить:
   - `←`, `→`, `Space`, `Home`, `End`;
   - экранные кнопки, focus-visible и полноэкранный режим;
   - touch/swipe;
   - hash-навигацию и восстановление текущего слайда;
   - viewport около `1440×900` и мобильный viewport около `390×844`;
   - печать всех слайдов и `prefers-reduced-motion`.
3. Проверить отсутствие ошибок консоли, сетевых запросов, обрезанного контента
   и горизонтального scroll.
4. Сообщить путь к презентации, число слайдов и выполненные проверки.

## Ограничения

- Не менять факты урока ради красивого повествования.
- Не скрывать сложность механизма за анимацией.
- Не создавать отдельный дизайн для каждого модуля.
- Не перезаписывать существующую презентацию без явного запроса или `--force`.
- Не добавлять изображения, если схема, код или таблица передают смысл точнее.
