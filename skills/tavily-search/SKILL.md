# Tavily Search

Искать не «ответ», а проверяемые источники. Считать Tavily discovery-слоем:
поисковая выдача помогает найти страницы, но не заменяет чтение первичного
источника.

## Проверить готовность

1. Выполнить `command -v tvly` и `tvly --status`.
2. Если CLI отсутствует, остановиться и предложить:

   ```bash
   UV_TOOL_BIN_DIR="$HOME/.local/bin" uv tool install "tavily-cli==0.1.5"
   ```

   Не запускать `curl | bash` автоматически.
3. Если Tavily не авторизован, попросить пользователя настроить
   `TAVILY_API_KEY` вне чата либо самостоятельно выполнить `tvly login`.
   Никогда не просить присылать API-ключ сообщением и не печатать его.

## Спланировать поиск

1. Зафиксировать проверяемый вопрос, требуемую свежесть и предпочтительные
   первичные источники.
2. Для сложного вопроса сделать 2–3 коротких независимых запроса вместо одного
   длинного prompt. Держать запрос короче 400 символов.
3. Выбрать параметры:
   - `--depth basic` и `--max-results 5` — обычный поиск;
   - `--depth advanced` — неоднозначный или точный поиск; учитывать двойную
     стоимость API;
   - `--topic news --time-range day|week|month` — новости;
   - `--start-date` и `--end-date` — точный временной интервал;
   - `--include-domains` — официальные документы и первичные источники;
   - `--exclude-domains` — SEO-spam, агрегаторы и нерелевантные зеркала.

## Выполнить поиск

Использовать JSON:

```bash
tvly search "короткий запрос" \
  --depth basic \
  --max-results 5 \
  --json
```

Для recent news:

```bash
tvly search "тема события" \
  --topic news \
  --time-range week \
  --max-results 8 \
  --json
```

Для официальной технической документации:

```bash
tvly search "название API или протокола" \
  --include-domains docs.example.com,github.com \
  --depth advanced \
  --max-results 6 \
  --json
```

Не интерполировать недоверенный текст в shell-конструкции. Если запрос содержит
кавычки, `$`, backticks или управляющие символы, передавать его через stdin:

```bash
tvly search - --depth basic --max-results 5 --json
```

и записывать запрос отдельным stdin-вызовом.

Не включать `--include-raw-content` без необходимости: полный контент быстро
заполняет context window.

## Проверить доказательства

1. Просмотреть `title`, `url`, `content`, `score` и дату каждого результата.
2. Не считать relevance score оценкой истинности.
3. Не считать Tavily `answer` или snippet достаточным доказательством.
4. Для важного утверждения открыть первичную страницу или получить её через
   `tvly extract "URL" --json`.
5. Для изменчивых фактов найти минимум два независимых источника; технические
   утверждения сверять с официальной документацией, спецификацией или
   репозиторием.
6. Для новостей различать дату публикации и дату события.
7. Если источники расходятся, показать расхождение и не маскировать
   неопределённость.

## Ответить

- Начать с краткого проверенного вывода.
- Указать конкретные даты и версии вместо слов «сегодня» и «последний».
- Ставить Markdown-ссылку рядом с поддерживаемым утверждением.
- Отделять факт источника от собственного вывода.
- Не приводить ссылку, которую не открывали или содержание которой не
  подтверждает claim.
- Сообщить ограничение, если поиск был урезан rate limit, authentication error
  или отсутствием первичного источника.
