# Правила работы в репозитории

## Цель

Этот репозиторий — практический трек подготовки Senior AI Agent Engineer.
Актуальные порядок модулей, промпты и критерии прохождения находятся в
[основном плане](docs/senior_ai_agent_engineer_2026.md). Если урок или
архивный пример расходится с планом, приоритет имеет план.

## Как вести обучение

- Считать студента Senior Python Developer с DevOps-опытом: не объяснять
  базовый Python, Git, Docker и CI/CD без явной необходимости.
- Идти по одному модулю и не переходить дальше, пока не выполнен его Gate.
- Сначала раскрывать contracts, invariants, state, failure model и механизм,
  затем реализовывать его с нуля, тестировать и только после этого показывать
  реализацию во фреймворках.
- Для практики сначала давать задачу, ограничения, acceptance criteria и
  проверяемый результат. Полное решение давать по запросу или после попытки
  студента; код студента разбирать как production review.
- Не усложнять систему агентностью без измеримого выигрыша относительно
  простого deterministic baseline.

## Проектные skills

При создании или обновлении интерактивной HTML-презентации для урока полностью
прочитать `skills/build-lesson-presentation/SKILL.md` и использовать его общий
шаблон. Основной план и правила этого файла имеют приоритет над skill.

## Правила реализации

- Новый материал размещать в `lessons/module_XX_topic/`; старые уроки в
  `lessons/legacy/` считать сравнительными примерами, а не текущим маршрутом.
- Не создавать пустой каркас всех модулей заранее.
- Предпочитать typed Python, явные модели состояния и небольшие заменяемые
  интерфейсы. Для I/O учитывать async, deadlines, cancellation и backpressure.
- Для side effects проектировать idempotency, retry policy, budgets,
  checkpoint/replay и audit trail.
- Вместе с happy path проверять contract, fault и security cases. Базовые
  тесты должны работать с deterministic fakes без live API.
- Для изменчивых API и протоколов сверяться с первичной документацией и
  фиксировать проверенные версию и дату в уроке либо ADR.
- Не изменять чужие незавершённые правки, секреты и файлы вне текущей задачи.

## Проверка изменений

Запускать сначала минимальные проверки затронутого модуля, затем доступные
проверки репозитория:

```bash
uv lock --check
uv run --frozen python -m compileall -q lessons
```

Изменение завершено, когда код и документация согласованы, команды запуска
актуальны, тесты проходят, а результат и выполненные проверки явно сообщены.
